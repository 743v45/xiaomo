# 小莫椭圆机 BLE 协议文档(MOBI000401 / SI0027)

> 来源:2026-09-22 iPad HCI 实抓(sysdiagnose,bluetoothd-hci-2026-09-22_20-29-48.pklg),
> 原版小莫 app 真实行为。**本协议与 qdomyos-zwift 的 ChangYow 老方案(0xF0/26B/1-15 档)不同代,
> 一切以本文档为准。**

## 连接

| 项 | 值 |
|---|---|
| 广播名 | `MOBI000401`(MOBI + 5 位数字) |
| 广播服务 | FFE0 |
| 主控 | Nordic nRF52(有 0xFE59 Secure DFU,**勿触碰**) |
| 配对 | 无需(nRF Connect / Chrome 均直连成功,链路未加密) |
| 服务 | FFE0 |
| 命令通道 | **FFE3**(handle 0x0010),Write / Write Without Response |
| 数据通道 | **FFE4**(handle 0x0012),Notify(订阅 CCCD 0x0013) |

## 帧格式(帧头 0xAB)

### 状态帧:机器 → app(FFE4 Notify,16 字节,1Hz)

```
B0    B1   B2   B3   B4   B5   B6   B7..B10        B11  B12  B13    B14
AB    04   15   0B   13   64   01   采样值(4B 大端) 00   00   档位   00
```

- **B13 = 当前阻力档位(1~24)**,写入目标后机器回报此字段,构成闭环
- **B7~B10 = 踩踏采样**(大端 4 字节):静止恒 0;踩踏时实测 1600~6800 区间波动,
  减速时递减、匀速时稳定——物理意义待标定(候选:功率×10 / 步周期 ms),当前按「强度值」使用
- B1=04 为状态帧类型号;B2~B5(15 0B 13 64)与 B6(01)在全部样本中恒定,语义待多状态采样确认

### 阻力命令:app → 机器(FFE3 Write,7 字节)

```
AB 03 00 0B 13 [LEVEL] 01      LEVEL = 目标档位(1~24)
```

- 实抓确认有效:写 23/22/…/8/7/…/5/4,机器逐档回报 B13
- **原版 app 采用斜坡下发**:目标与当前相差多档时,每 **~150ms** 逐档发一帧(23→22→…→8),
  不跳变;自研 app 建议沿用(或带 250ms 防抖直接跳,待真机验证机器接受度)

### 无启停命令

抓包全程(连接→踩踏→调阻→停止→断开)**未出现**开始/暂停/结束类命令帧:
机器自动检测踩踏并上报,「开始/暂停/结束」是小莫 app 的本地概念。自研 app 可完全自主定义。

## 档位

**1~24 档**(实测写入 4~23 均有效、回报一致;实抓最高见 24)。qdomyos 的 1-15 限制不适用。

## 待标定 / 待确认

- [ ] B7~B10 采样值的物理换算(速度/RPM/功率)——需已知速度对照实验
- [ ] 卡路里/距离机器不上报,需 app 端基于采样自行计算(模型待标定)
- [ ] B1 类型号是否有其他值(面板按键上报等)
- [ ] B2~B5、B6、B11~B12、B14 语义
- [ ] 直接跳档写入(不斜坡)是否被机器接受
